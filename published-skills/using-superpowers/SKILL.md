# 使用 Superpowers

本 Skill 是克制的 Skill 路由器。自动检查不等于自动建议，也不等于自动调用。

## 何时检查

在以下时点静默检查一次：

- 每个新用户请求；
- 明显的任务转折点，例如目标改变、探索转入设计或实施、关键假设被新证据推翻、单一任务拆成多个独立任务，或当前方案已不可行。

不要在每次回复、工具调用、读取文件或执行普通步骤之前重复检查。

## 可以使用的上下文

按以下范围渐进理解当前问题：

1. 当前聊天中的多轮对话；
2. 用户明确提供或当前任务已经涉及的文件、Spec 和链接；
3. 当前任务中已经读取、创建或修改的文件；
4. 为理解上述材料所必需的少量直接相关文件。

从成本最低、相关性最高的信息开始；每扩大一层，都必须是为了理解当前问题；一旦足以判断是否建议 Skill，就停止扫描。

不得为了寻找使用 Skill 的理由而大范围扫描仓库、浏览网页或展开额外调查。信息不足时先正常澄清，问题明确后再判断。

## 如何处理 Skill

### 用户显式调用

用户明确指定某个 Skill 时，若该 Skill 已启用且所需依赖可用，直接读取并遵循它。

若 Skill 未安装、未启用，或依赖的 Skill 尚未发布和安装，不得调用、替代或模拟它。简短说明当前不可用，然后继续处理无需该 Skill 也能完成的部分；等依赖以后发布再使用。

### 自动检查后的建议

只有同时满足以下条件，才向用户建议 Skill：

- 当前存在一个具体问题，而不是抽象的“可能有帮助”；
- 能说明使用该 Skill 的预期收益；
- 能说明主要成本，例如增加步骤、时间、文档或用户确认；
- 该 Skill 已启用，且其必需依赖可用。

建议时只推荐净收益最高的一个 Skill，并使用简短格式：

> 当前问题是……；使用 `$skill-name` 预计能……；成本是……。要启用吗？

获得用户明确同意后才调用。用户拒绝后，本次任务中不要重复建议；只有出现重要新证据、收益发生实质变化或任务性质改变时，才可重新评估。

### 已单独批准自动调用的 Skill

如果某个 Skill 已由用户单独批准自动调用，并且其 `SKILL.md` 和平台元数据给出了狭窄、可观察的触发条件，可按该 Skill 的规则直接调用。不要把本 Skill 的自动检查解释为对其他 Skill 的自动授权。

## 多个 Skill 同时相关

不要列出 Skill 菜单。比较它们对当前具体问题的收益、成本和依赖，只建议净收益最高的一个。其余 Skill 等任务性质变化后再评估。

## 无需打扰用户的情况

没有合适 Skill、收益不足以覆盖成本、依赖不可用，或普通处理已经足够时，保持安静并继续任务。

## 平台适配（按需读取）

不要在日常路由检查中读取平台参考文件。只有已经决定使用某个下游 Skill，而且该 Skill 确实涉及子 Agent、任务追踪、工作树、分支收尾或平台工具映射时，才读取当前运行环境对应的一个文件：

- Codex：`references/codex-tools.md`
- Gemini CLI：`references/gemini-tools.md`
- Pi：`references/pi-tools.md`
- Antigravity：`references/antigravity-tools.md`
- Hermes Agent：`references/hermes-tools.md`

平台参考与当前工具列表或更高优先级指令冲突时，以当前运行环境为准。不要为了读取参考文件而调用原本无需使用的下游 Skill。

## 优先级

用户的直接要求以及适用的 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 等项目指令优先于本 Skill。
