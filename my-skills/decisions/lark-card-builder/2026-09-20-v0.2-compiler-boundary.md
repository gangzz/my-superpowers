# lark-card-builder 0.2 编译器边界

## 问题来源

真实飞书 API 曾拒绝 Builder 已成功编译的表单卡：OpenAPI `230099`，内部错误 `10002`，原因是表单组件同时设置 `required=true` 与 `disabled=true`。这证明“结构可编译”还不等于“满足已知飞书语义规则”。

## 本版责任

`lark-card-builder` 是飞书 Card JSON 2.0 的受支持子集编译器。`ok: true` 代表：

- CardSpec 结构、已知跨字段语义和容器上下文合法；
- 生成结果使用 Builder 已验证的官方字段；
- 每张物理卡片的递归组件数不超过官方 200 上限；
- 结果经过编译后复检，并公开规则快照、稳定摘要和 UTF-8 字节数；
- 调用方指定的更严格卡片字节限制得到执行。

它不代表鉴权、网络、群访问、发送成功或多卡原子交付。Builder 不负责发送、重试、Outbox、Workspace 解析或 FeiForge 私有 callback 语义。

## 规则来源边界

- 只把官方文档快照或脱敏后的真实 API 错误证明过的约束写成内置规则。
- 未确认的 callback 大小或字段长度不猜数值；调用方可以通过消费者限制收紧，不能放宽官方硬限制。
- Builder 未覆盖的官方 Card JSON 2.0 能力可由调用项目直接使用，但不享受 Builder 校验、摘要和自动分片保证。
- 不增加 `rawElement()` 或任意字段注入。

## 兼容与版本

- npm 包升级到 `0.2.0`，CardSpec 继续使用 `specVersion: 1`。
- 合法的 0.1 CardSpec 继续有效。
- `snapshot` 保留一个兼容周期并等于新增的 `rulesSnapshot`。
- 删除可放宽官方上限的公开 `hardLimit`；`targetBudget` 仍可设置，但范围固定为 1–200。
- TypeScript Builder 的现有 Markdown `content` 保留；新增结构化安全片段供 JSON/CLI 调用。

## 真实错误回归原则

每次飞书在线拒绝暴露新的确定规则时，保存脱敏后的错误码、路径、消息、最小 CardSpec 和期望本地 issue。同一种确定性 400 错误不应在线上重复出现。
