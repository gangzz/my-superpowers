# lark-card-builder 0.2.1 证据与输出身份

## 问题

0.2.0 已解决真实的 `input required + disabled` 拒绝，但又把该结论推广到了 `staticSelect`，并增加了若干只有“看起来合理”而没有拒绝证据的硬错误。能力查询还混用 CardSpec kind 与官方 tag，CLI 也无法传入 API 已支持的消费者限制。`specDigest + part` 不能唯一标识不同预算下的物理分片。

## 决策

- npm 包升级到 `0.2.1`，CardSpec 仍为 `specVersion: 1`。
- `OFFICIAL_LIMITS` 成为 schema、compiler 和 capabilities 的唯一数值来源；每个限制指向字段级官方快照来源。
- 官方组件目录、支持状态和 CardSpec 映射由同一份 `OFFICIAL_COMPONENT_CATALOG` 派生，补入 `picker_datetime` 和嵌套 `column`。
- CLI 支持 `targetBudget`、`maxCardBytes`、`maxCallbackBytes`，与 TypeScript API 使用同一编译入口。
- 新增 `bundleDigest`，覆盖逻辑摘要、实际目标预算、Builder 版本、规则快照和有序物理卡摘要。
- 真实 230099 规则只应用于 `input`。撤销 `staticSelect required + disabled`、`disabledTips`、`maxRows` 和初始选项组合的无证据硬拒绝。
- `staticSelect.initialOption` 按官方“选项内容”透传；`initialIndex` 保持官方 1-based 语义，`0` 表示不选择。

## 边界

Builder 允许飞书文档声明为“不生效”但未声明非法的组合；这不等于承诺其产生业务效果。若真实 OpenAPI 拒绝暴露新规则，必须先保存脱敏回归证据，再收紧本地编译。

本版只更新开发区。发布目录、安装链接、Git commit、tag 和 push 均需单独授权。
