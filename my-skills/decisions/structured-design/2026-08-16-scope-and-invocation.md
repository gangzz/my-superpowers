# structured-design：范围与调用方式

## 背景

复杂工程设计、项目方案、业务流程和思路分析经常同时包含实体关系、流程、状态、层级、依赖和边界。仅靠连续文字会把结构留给读者在脑中重建；仅画图又容易缺少目的、约束和反直觉说明。

现有 Claude Code 全局规则已经包含较长的图文表达规范，Codex 全局规则只有简版。继续分别维护会产生跨平台和跨电脑漂移。

## 决定

- 创建原创个人 Skill：`structured-design`。
- 使用同一份标准 `SKILL.md` 支持 Codex 和 Claude Code。
- 采用“结构优先、渐进展开、图为主线、短文字补边界”的表达方式。
- 详细规范和工程、项目、业务、复杂分析四类示例放入 `references/`。
- Codex 的 `agents/openai.yaml` 设置 `allow_implicit_invocation: true`。
- Claude Code 不设置 `disable-model-invocation`，允许根据 `description` 自动匹配。
- Codex 全局 `AGENTS.md` 与 Claude Code 全局 `CLAUDE.md` 只保留相同的 Skill 路由和简短退化规则，不复制详细规范。

## 触发范围

在任务的主要理解成本来自以下一个或多个方面时触发：

- 实体、模块或角色关系；
- 数据、责任或业务流程；
- 对象生命周期和状态；
- 总分、聚合或依赖层级；
- 人工边界、系统边界和停止位置；
- 多方案权衡、因果和二阶影响。

典型任务包括系统架构、数据模型、Spec、项目方案、业务流程、服务设计和复杂思路分析。

以下任务不触发：简单事实、短说明、单步操作、普通进度更新、短文案，以及用户明确不要图示的任务。

## 用户控制

- Codex 可通过 `$structured-design` 显式调用。
- Claude Code 可通过 `/structured-design` 显式调用。
- 用户要求简短回答、不要图或停止展开时，立即降低表达层级。
- 即使 Skill 已触发，图不能显著降低理解成本时也改用短文字、列表或表格。

## 验收

### 应触发

1. “给我画出这个系统的实体关系、数据流和任务状态，再逐章展开 Spec。”
2. “这个项目有多个阶段和依赖，我想先看到全景，再讨论当前阶段。”
3. “把市场、销售和运营之间的客户交接流程讲清楚。”
4. “帮我结构化比较自建和采购，标出可能改变结论的问题。”

### 不应触发

1. “把这句话翻译成英文。”
2. “当前测试通过了吗？”
3. “告诉我怎么执行这个单条命令。”
4. “只用三句话解释这个概念，不要画图。”

## 发布边界
