# test-map：名实抽查与增量自动调用

## 背景

初版（同日 `2026-08-19-initial-design.md`）定为仅手工调用、只读测试名。用户随后提出两点：

1. 只读测试名无法确定测试的实际覆盖与名字相符。
2. 本 Skill 与其它 Skill 性质不同——地图需要随代码增长持续生成，应允许主动调用，且必须是增量模式，避免每次全量扫描。

## 决定一：名实抽查

信任缺口按测试来源分两路补：

- 自己用 TDD 流程写的测试：Verify RED（亲眼看测试以正确原因失败）在写入时已保证名实相符，不抽查。
- 存量/他人测试：首次建图时每场景抽 1–2 条、合计不少于 5%，读实现核对断言与名字；相符率写入交付报告，不符的标注存疑并列给用户。抽查是本 Skill 唯一允许读测试实现的环节。

理由：全量读实现摧毁"低成本"这一存在前提；零验证则是盲信。有界抽查换置信度声明，成本可控（约 142 例只需读 8 条）。

## 决定二：增量模式自动调用（用户批准）

按 CLAUDE.md 自动调用评估要求逐项落实：

- **狭窄可观察的触发**：项目已存在 `test-map.json`，且本次会话新增/修改/删除了测试。
- **明确排除**：本次未改动测试；项目没有测试；用户说过不要自动更新；首次建图（仍需用户同意——全量扫描、聚类、抽查成本高且含判断）。
- **用户控制点**：每次自动更新后必须汇报增量；新增场景必须提议而非擅自扩；用户可随时停用。
- **安全回退**：自动模式只写 `test-map.json` 和 `test-map.html` 两个文件，git 可直接回滚。

增量的技术锚点：JSON 顶层 `anchor`（commit + generatedAt）。定位变更优先用会话内已知的改动文件，跨会话用 `git diff --name-only <anchor.commit>` 过滤测试文件；与已记录案例求差集后只归类差集。不推翻已有聚类，防止地图漂移。

用户确认接受 git 依赖（2026-08-19）。补充澄清：增量真正节省的是归类而非扫描——grep 全量提取本身成本很低，且案例差集靠 JSON 已记录清单计算，与 git 无关。因此无 git 项目的降级是"全量提取 + 差集归类"，仍保持增量语义；不使用 mtime（checkout、复制均会污染该信号）。

`agents/openai.yaml` 相应设为 `allow_implicit_invocation: true`，并注释指回本记录；这是本仓库第一个获准自动调用的 Skill。

## 未解决

- Claude Code 侧没有等价的机器策略开关，自动触发依赖 SKILL.md 文字被遵守；如发现过度触发，收紧触发条件或退回手工。
