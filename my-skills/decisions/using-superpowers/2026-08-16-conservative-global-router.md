# using-superpowers 克制式全局路由决策

## 背景

上游版本要求只要存在极低概率相关性就直接调用 Skill，并把检查置于每次回复、澄清和文件查看之前。实际使用中，这会让简单任务不断进入重型流程，明显降低开发效率。

## 决策

- `using-superpowers` 可以自动触发，但它只负责静默检查和适时建议，不自动授权其他 Skill。
- 在每个新用户请求或明显任务转折点检查一次，不在每次回复或工具调用前重复检查。
- 可以理解当前聊天的多轮上下文和任务已涉及的材料，并按最小必要范围渐进读取直接相关文件。
- 不得为了寻找 Skill 使用理由而大范围扫描仓库、浏览网页或扩大调查。
- 只有能说明具体问题、预期收益和主要成本时才建议，并且一次只建议净收益最高的一个 Skill。
- 除用户显式调用或目标 Skill 已单独获准自动调用外，必须得到用户明确同意后才调用。
- 用户拒绝后不重复建议，除非出现重要新证据、收益实质变化或任务性质改变。
- 只考虑已经启用、安装且依赖可用的 Skill。Skill 或其依赖尚未发布和安装时，暂不执行，不做替代或模拟。

## 发布与部署

- 本次用户明确同意直接发布并全局启用，不设置候选期、状态脚本或额外评估流程。
- 发布目录仍是唯一安装来源；开发目录不直接安装。
- Codex 和 Claude Code 都通过软链接指向同一个发布目录。
- 全局 `AGENTS.md` 和 `CLAUDE.md` 只保留一条启动提示，完整路由规则只在本 Skill 中维护。
- 不发布上游的平台工具映射参考；它们与路由职责无关，且会增加全局上下文成本。
- 若实际使用出现问题，可以关闭隐式调用或移除全局软链接回退。

## 验收标准

- Codex 元数据允许隐式调用。
- 开发版和发布版结构验证通过。
- 全局安装链接只指向 `published-skills/using-superpowers/`。
- 未执行 Git commit、tag 或 push。
