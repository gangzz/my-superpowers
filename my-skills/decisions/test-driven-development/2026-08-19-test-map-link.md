# test-driven-development：链接 test-map（面向人的交付）

## 背景

用户诉求：Agent 写出的测试要让人低成本读懂、能参与。经讨论决定不把测试呈现流程塞进本 Skill，而是新建原创 Skill `test-map`（见其决策记录），本 Skill 只加引用。

## 改动

在"好的测试"与"常见自我合理化"之间新增"面向人的交付"一节（4 行）：

- 测试名描述行为、describe 按场景分组，让测试名列表读起来就是行为规格。
- 开发完成后用户需要测试全貌时，用 test-map Skill 交付三层测试地图；已有地图只汇报增量。

## 理由

- 命名与分组约定是 TDD 写测试环节的产物，放本 Skill；呈现与汇报是独立环节，放 test-map，避免铁律正文被模板说明稀释。
- 引用而不复制，保持本 Skill 与上游的可对比性。
