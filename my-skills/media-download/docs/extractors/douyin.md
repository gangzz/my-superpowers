# Extractor 决策记录：`douyin`

## 范围

- 首期目标：用户指定的单个抖音公开作品。
- 排除范围：搜索结果采集、个人主页批量下载、直播、评论全量采集和直接转写。单作品最多 40 条公开一级评论的可选采样见本页后文。
- 首次探针的预期内容：视频。未来支持图文作品时，现有框架无需修改核心契约。

## 当前能力

- 浏览器能力：`headless-verified`，普通下载默认 Headless；验证范围见下文。
- Profile：使用 media-download 的本机默认持久化 Profile；它与日常 Chrome 和其他项目隔离，但与本 Skill 的其他站点共享。
- 访问状态检测：由抖音 Extractor 在作品入口链路中返回 `ready`、`login_required`、`captcha` 或 `unavailable`。
- 人工处理入口：失败 Job 使用 Extractor 决定的登录或作品入口；人工选择清晰度直接打开目标作品。
- 入口链路：完整作品链接与带 `modal_id` 的链接直接解析作品 ID，分享短链先通过 HTTP 重定向解析 ID；下载和失败任务人工接管统一使用 `jingxuan?modal_id=<id>` 作品入口。来源记录仍保留 `/video/<id>` 规范作品 URL。
- 验证码判断：只接受可见且在视口内的验证组件／弹层及其验证提示、滑块／画布或验证码 iframe；隐藏、透明或位于隐藏祖先内的组件，以及正文单独提及验证码，均不构成人工接管依据。可见验证弹层优先于背景中的可播放视频；缺少目标数据仍必须失败，不因视频可播放就忽略身份校验。
- 目标绑定：从输入或跳转后 URL 取得作品 ID，在 `RENDER_DATA` 中找到同 ID 的目标对象，直接使用该对象内的视频 URL 生成 Manifest。
- 来源记录：只保存由作品 ID 构造的规范作品 URL，并写入目标对象中的作者平台 ID、昵称、主页链接、明确作品标题、完整发布文案和结构化话题标签；不保存跳转页或输入 URL 的查询参数。
- 互动快照：从目标作品对象读取可用的点赞、收藏、评论和分享计数，明确忽略播放量。顶层 `downloadedAt` 作为同次快照时间；目标对象未提供的计数直接省略。
- Transport 模式：目标 `RENDER_DATA` 中的合并资源和显式分离轨道都使用 `browser-session`。当前 Context 的会话材料随连续 Range 请求发送，响应以有背压的流写入磁盘。

## 已确认决策

- 生产链路从 Headless 默认 Profile 起步；是否需要登录由当前作品入口的访问状态决定。
- `RENDER_DATA` 不提供可靠的“当前播放器资源”标记；默认按共享 Selector 的无当前标记回退规则选择合并资源，合并资源不可用时才选择视频轨和音频轨进行封装。
- 用户明确要求选择清晰度时，先打开目标作品供用户操作；关闭前读取当前视频尺寸，再提交带期望尺寸的普通 Job。
- 最终候选以实际媒体轨道检查结果为准。
- `blob:` 是页面的 MediaSource 播放地址，不能直接下载，且它本身不表示音视频分离。
- 三个 `blob:` 播放样本通过页面请求与 `ffprobe` 验证，分别为 `3840×2160 / HEVC+AAC`、`3840×2160 / HEVC+AAC`、`576×1024 / HEVC+AAC`，都是音视频合并 MP4。
- 抖音 CDN 资源不应依赖页面脚本重新 Fetch；同一 Context 会话材料的 Range 请求用于合并资源和显式分离轨道。当前实机样本已完成 `138,745,420` 字节视频轨与 `6,783,516` 字节音频轨下载、无损封装和 `ffprobe` 验证，最终文件 `145,933,975` 字节、`576×1024`、含音轨。
- 两种传输都不读取完整 `arrayBuffer`；数据逐块进入 Node 写流。最终文件通过轨道、尺寸、大小和 SHA256 检查后再提交。

## 开发与修复契约

1. 正式下载在 Headless 模式下使用本机默认 Profile，为当前任务创建独立页面；不启动 `NetworkProbe`。
2. 在浏览器导航前解析分享短链的 HTTP 重定向和作品 ID；打开规范化作品入口并按作品 ID定位目标 `RENDER_DATA` 对象。
3. 只从该目标对象生成候选和内容元数据；作者身份缺失时停止，不把页面标题冒充作品标题，不记录播放量。
4. 用最终 `ffprobe` 检查区分仅视频、仅音频和音视频合并版本。
5. 开发或修复站点逻辑时，可以在外部临时现场使用 `src/dev/network-probe.mjs` 对照页面实际请求；它只提供证据，不得成为 Extractor 输入。
6. 关闭当前任务页面；队列排空后，验证 BrowserHost 已关闭 Context、Profile 已保留、锁已释放，并且没有遗留的所属进程。

登录失效或 CAPTCHA 进入可见人机接管；目标不匹配、进程归属不清或媒体连续失败进入停止状态。身份和浏览器模式由人工决策保持或变更。

## 当前验证边界

- 目标 `RENDER_DATA` 直接发现路径已用公开作品完成端到端实机验证，全程未启动 `NetworkProbe`。
- 页面内 `fetch` 对同一 CDN URL 返回 `Failed to fetch`；改用当前 Context 会话材料的 `browser-session` 后成功交付 `210,523,562` 字节、`576×1024`、时长 `889.695782` 秒且含音轨的 MP4，并完成 SHA256 检查。

### 2026-11-17 Headless 验证证据

用户指定的「梳理对标账号定位下一步」对话中，使用现有正式 Extractor、Selector、Transport 和 Verifier，只通过 BrowserSession 的 driver 注入将启动参数改为 `headless:true`，在新建匿名 Profile 上验证了两位作者的作品 `7707481055191649599`、`7708964739254144292`。作者和作品 ID、音视频轨、大小与 SHA256 均通过；进程参数确认存在 `--headless`，后续批次继续成功。该结论支持普通公开视频默认 Headless，不代表所有登录态、入口和作品等价。原试验没有改正式 Skill。

两条样本的评论仍为未取得，与此前可见模式结果一致，不能写成评论 Headless 已验证成功。当前更新只晋级抖音能力；B 站不变。登录／验证码／人工清晰度选择仍必须打开可见浏览器，不自动重试或隐藏接管窗口。

## 后续资格验证

- 当前播放器清晰度是否跨页面、跨 Context 重启稳定保存在 Profile 中。
- 创作者个人主页点击链路与完整作品长链接是否生成等价 Manifest。
- Headless 在登录态 Profile、清晰度选择后以及评论成功采样场景的覆盖；不能由匿名视频下载通过推定。

## 可选公开评论采样

用户指定 `--comments 1..40` 时，身份核实后先关闭可关闭的登录提示与新手引导，从目标视频容器的 `feed-comment-icon` 打开 `comment-list`，再通过原生“继续看评论”按钮关闭评论区提示。提示处理归属于本Extractor的评论模块，调用项目传入数量上限并验收实际状态。读取一级 `comment-item`，根据语义类 `comment-item-info-wrap` 与 `comment-item-stats-container` 定位昵称、正文、显示时间和点赞文字；评论 ID 取自本条更多菜单 tooltip ID。表情取图片 alt，不保留图像 URL。滚动当前评论列表、保持首次出现顺序且按 ID 去重；不展开回复、不改排序、不调用私有签名接口。

实机样本 `7622273330103586083`：2026-11-06 本机独立 Profile、可见浏览器，采得 37 条一级评论，页面显示末尾；状态 `exhausted_visible`。同页平台总数为 53，不能以总数推定一级评论采样应有多少条。其他评论加载结构与未登录场景尚未实机覆盖；取不到时返回明确状态，媒体下载仍可独立成功。

2026-11-17匿名Headless复测中，作品 `7622273330103586083` 关闭上述提示后显示10条一级评论，列表底部明确显示“登录后可看更多”。滚动到列表底部仍停在10条。采集器据此返回 `partial` / `login_required`，请求上限保留为40。该结果说明当前匿名访问存在登录边界。历史37条样本的独立Profile状态与本次全新匿名Profile不同，须按本次访问条件解释数量差异。
